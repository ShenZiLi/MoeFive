## 4.2 俯视棋子四套方案

四套方案均为黑白棋子组合预览图，采用正上方视角，适合用于确定最终棋子 UI 方向：

| 方案 | 视觉关键词 | 适合的产品气质 | 当前建议 |
|---|---|---|---|
| 方案一：爪印黏土 | 爪印、识别度高、与现有场景一致 | 萌宠主题最直接、最稳妥 | **正式方案** |
| 方案二：萌宠脸谱 | 小狗/小猫鼻口与耳朵符号 | 角色化最强，辨识玩家阵营 | 备用皮肤 |
| 方案三：花朵治愈 | 粉蓝花朵、叶片、自然感 | 温柔、轻松、治愈 | 备用皮肤 |
| 方案四：爱心糖果 | 爱心、糖果色、圆点装饰 | 轻快、社交、节日感 | 备用皮肤 |

当前正式方向为方案一。四张方案图均保留在 `assets/pieces/schemes/` 中；接入 Godot 前应将方案一裁切为独立的 `black_piece.png` 与 `white_piece.png`，并统一导出尺寸和透明边距。其余三套保留为备用皮肤，不删除。

## 7. 当前缺口与风险

| 问题 | 影响 | 建议 |
|---|---|---|
| 大量内容烘焙在一张背景图中 | 无法单独替换角色、植物、木牌或黑板 | 后续拆分为独立图层资源 |
| 棋子仍是程序化圆形 | 与原型中的萌宠角色表现不完全统一 | 制作独立黑子、白子或角色化棋子 |
| UI 使用程序化绘制 | 与背景图的精致黏土材质存在落差 | 制作按钮、玩家卡、气泡和木牌等 UI 资源 |
| 角色无法单独动画 | 胜利、失败、思考等表现受限 | 拆分角色立绘或序列帧 |
| 背景图无透明通道 | 不适合作为可组合图层 | 保留底图，同时补充透明 PNG 图层 |
| 字体依赖系统路径 | 跨平台打包后可能缺字 | 内嵌授权可商用中文字体 |
| 备选棋盘未接入运行时 | 方案文件较多但缺少资源分层 | 标记为参考资源或清理未采用版本 |
| 资源未全部纳入版本控制 | 克隆或交付时可能缺少运行资源 | 将 `assets/` 与 `.import` 配置纳入 Git |

## 9. 结论

当前项目已经确立了清晰的暖色木质 × 黏土萌宠视觉方向，主场景底图完成度较高。

但当前仍属于“单张合成图驱动的 M2 原型阶段”：

1. 运行时核心美术资源只有一张完整场景图。
2. 棋子和 UI 主要由程序化绘制完成。
3. 狗猫角色、植物和装饰物还不能独立替换或动画化。
4. M3 美术工作重点应放在图层拆分、角色状态、独立棋子、UI 组件、动效和字体资源上。
